# Changelog

All notable changes to the AgenticNets open-source services are documented here.

This file holds only the **current calendar quarter's** releases. Older
quarters are archived under [`changelogs/`](changelogs/) — see
[`changelogs/README.md`](changelogs/README.md) for the index. At the end of
each quarter, the entries below get moved into a new `changelogs/CHANGELOG-YYYY-Qn.md`.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [2.61.0] - 2026-10-25

### Added
- **Focus 1.6.0 guided rounds; headless-agent 1.0.1; MCP `focus_round` and `focus_rounds`** (`agentic-net-apps/examples/refiner`; `capabilities/headless-agent`; `agentic-net-mcp` - `focus-rounds.ts`; `agentic-net-gateway` tests). Focus gains the stores `rounds`, `round-jobs`, `round-commands`, `round-raw`, `round-results`, the guarded actions `createRound` and `dispatchRound`, the lanes `t-refiner-round-build`, `-run` and `-shape`, a `guided-round` prompt seed and a Codex read-only profile seed. A round's agent runs without MCP and returns proposals that the master validates and applies. headless-agent runs a job without a source folder in a temporary folder holding `model-round.json`, removed afterwards, and takes `HA_RESULT_KEY` for the result marker. With review tools enabled, MCP clients start, answer, refine and retry a round with `focus_round` and read it with `focus_rounds`.
- **Focus 1.5.0 declares its own page** (`agentic-net-apps/examples/refiner` - `surface.renderer: focus-work-v1`; `agentic-net-mcp` - `refine.ts` wording). Focus is an application page under Applications (Studio renders the declared surface), not a view of the Model Explorer; its prompts and hints say so. Nothing else in the package changed; an upgrade keeps every token and the MCP grant.
- **MCP access declared and granted on consent** (`agentic-net-mcp` - `application_mcp`, `hub_install`, `hand_over`; `agentic-net-apps` - Focus 1.4.2, packer; `capabilities` - `pack.mjs`, `CONTRACT.md`, Steward 0.3.2). `application_mcp {name, action: state|grant|revoke}` reads and changes the MCP access an installed package asks for; `hub_install` takes `grantMcp`. `hand_over` names a missing grant and no longer attaches this server to the lane itself. `capability.yaml` may declare an `mcp` block (pack.mjs carries it into the agent manifest and checks its lanes); the Steward declares the token its ten command lanes use. Focus 1.4.2 declares its review tools; the app packer checks the block.
- **headless-agent: one runner for a coder; Focus 1.4.1** (`capabilities/headless-agent`, `capabilities/tools/pack.mjs`; `agentic-net-apps/examples/refiner`; `agentic-net-mcp` - `refiner_configure`, `hand_over`). The capability's script runs a headless CLI agent (Claude Code, Codex) once in a folder under a profile token and enforces read-only itself: reading tools only, shell and write tools always disallowed, bypass flags refused, Codex always in the read-only sandbox and never given an MCP server. An MCP server reaches the agent only as a private config limited to the caller's tools, and token variables stay out of its environment; `verify/test_headless_agent.py` proves the rules with fake binaries. Focus 1.4.1 keeps its prompts and coder profiles as seeded tokens and runs its coder in its own lanes through the runner; every value in that command's env is a template, because the importer redacts literal env values. `refiner_configure {root, profile, model}` replaces the coder name (claude and codex map onto the read-only profiles); `hand_over` says how to install the runner when it is missing. `pack.mjs build` keeps a place declared as a store when no lane uses it.
- **Application views over MCP, seed defaults that can be upgraded, levels without locks** (`agentic-net-mcp` - `application_view`, `net_levels`; `capabilities/tools/pack.mjs`, `CONTRACT.md`). `application_view` reads an application's declared view (one server-side fold, the same Studio shows). `pack package` marks capability seed tokens `_seed`, so an upgrade replaces a seed the person never edited and keeps an edited one. `net_levels` no longer has `locked`/`lockNote`: levels carry no permissions.
- **Applications bring their own MCP prompts; the Explorer's structure reads under neutral routes** (`agentic-net-mcp` - `app-prompts.ts`, `prompts.ts`, `explore_model`; `agentic-net-apps` - Focus 1.3.0, Kanban 1.0.1, Approval Room 1.1.1, packer, SDK). An application manifest may declare `agentProtocol.prompts` (arguments, `requiresTools`, a template with `{{value}}`, `{{#v}}`, `{{^v}}` and pattern sections `{{#v=~regex}}`); the MCP server reads them from the NetHub catalog in the background and registers each only where every tool it names is registered, so the review method's five prompts (now in Focus 1.3.0) appear exactly with its tools; a clashing name is registered as `<application>-<name>`. `explore_model` reads the catalogue, facts, chain and slice from `/api/models/{m}/structure` and falls back to the Explorer routes on an older master. The SDK runtime gains an optional `viewer()` (the name declared in Studio, a label, not a login); Kanban and Approval Room prefill "Acting as" from it. Focus 1.2.1 reports the pass kind it ran. The MCP knowledge names both relation systems.
- **Explorer, Phase 1 of the extraction** (`agentic-net-mcp` - `explore_model`, `config.ts` `AGENTICOS_REVIEW_TOOLS`, `server.ts`, `prompts.ts`, `create_model`; `agentic-net-desktop` - `mcp.reviewTools`; `agentic-net-apps/examples` - Focus 1.2.0, Curation 1.4.2). `explore_model` carries the core reads as options: `facts:true` (the structural facts of the matched nets), `slice` (one feature across its levels) and `chain` (a net and the nets above it). The review method's ten tools and five prompts register only with `AGENTICOS_REVIEW_TOOLS=true` (default off; on a Desktop the setting `mcp.reviewTools=true`, which the hand-over coder needs); a tool called on a model without the application answers `{available:false, reason:"not-installed", application}`. The Refiner package is shown as Focus; Curation speaks of sources, not code; `get_net_definition` asks with Interview 1.7.0's `refs {"explorer.build": id}` next to `buildId`; `create_model` accepts the `modeling` profile.
- **Explorer hand-over, Phase 0 of the extraction** (`agentic-net-mcp` - `hand_over`; `agentic-net-desktop` - launcher). The MCP server attaches itself to the Refiner's lane with a tool allowlist (the review tools only). A hand-over that finds applications missing names `hub_install` for them instead of installing. The Desktop launcher hands the master its MCP endpoint, the token file and the speech service as configuration. Refiner 1.1.2 reads the request's `passKind`; the review prompts name `update_net_definition {action:"create"}` for a new definition.
- **Hand-over to the AI over MCP** (`agentic-net-mcp` - `hand_over`, `refiner_configure`, `refiner_status`, `subject_thread`, `curate_model`; `agentic-net-apps/examples` - Refiner 1.1.0, Curation 1.4.0). `hand_over` runs a refinement pass (on the coder once a sources folder is configured, else in the model's agent lane; `runner` picks one), or one of `structure`, `ground`, `look`, `explain`, `check`, `draft`, `diff` on a read-only headless coder (Claude Code or Codex) in the folder of the model's sources on the executor, with an optional `card` that goes into the coder's prompt; a coder kind without a sources root answers `needs-setup` and names `refiner_configure {root, coder, coderModel}`. `subject_thread` reads everything said and decided about a subject; `curate_model note` takes `noteKind` `brief`, `summary`, `decision` and `finding`. The Refiner application gains a `config` store and a `configure` action, request fields `runner` and `card` and the status `delegated`; Curation 1.4.0 adds the `finding` note. Refiner 1.1.1: the lane takes the newest open request first.
- **Typed questions for llm transitions over MCP** (`agentic-net-mcp` - `add_transition`, `add_transitions`, `questions.ts`). `questions`, `state` and `questionVersion` build an llm lane that asks bounded questions (choice, score, probability) instead of a prompt; they are validated before anything is written. `llm_groups` reports `decisionModel` for groups on a decision model such as TypeSafe Jev. Deployment and Desktop Lite docs describe the `typesafe` and `decision-api` provider instance types.
- **Local speech service** (`deployment/speech/speech_service.py`, `agentic-net-desktop` - `speech.url`). Dictation and reading for Studio, open source and on device: `POST /transcribe` (whisper.cpp, Metal on Apple silicon; any clip, ffmpeg converts it) and `POST /speak` (Piper voices, macOS `say` as the fallback before a voice is downloaded). Studio reaches it through the master's `/api/speech` (see core); the Desktop forwards `speech.url` from `desktop.properties` to the master, default `http://127.0.0.1:8092`. The README has a table of where the voice goes for each choice. Measured on an M-series Mac with `ggml-small`: a six-second sentence transcribed word for word in 8 s on the first call (model load included), a card of 40 words spoken by Piper in 1.2 s.
- **Focus scopes over MCP** (`agentic-net-mcp` - `focus_scope`, `refine_model`, `focus_digest`, `ground_model`, prompts `refinement-pass` and `structure-pass`). `focus_scope {scope}` reads one feature across its levels, what surrounds it and the levels its chain passes without a net of its own; `refine_model`, `focus_digest` and `ground_model` take `scope` (and `ring` for the open decisions around it). With a focus scope the two pass prompts first look around: settle each gap from the sources and the other features on that level, read the neighbours for changes that affect the scope, raise what other features have that the scope lacks, and record the pass under the scope. Scope subjects count as level subjects in `curate_model`.

### Fixed
- **Focus 1.6.1: a round without a source folder ran nothing** (`agentic-net-apps/examples/refiner` - `t-refiner-round-build`). The round context bound as an object and the executor leaves objects out of a command's environment, so the runner saw no context and refused with an empty `HA_ROOT`. The lane passes it through `json()`.
- **`explore_model` says when the model is still loading** (`agentic-net-mcp` - `explorer.ts`). A master that answers 503 `loading: true` for the catalogue (the node loads the model after a restart) now yields `available: false, loading: true` with a hint to ask again, instead of an error or, on older masters, an empty overview.
- **Focus tools answer what is really missing** (`agentic-net-mcp` - `tools/refine.ts`, `tools/explorer.ts`, `tools/definitions.ts`). A 404 is either "Focus is not installed", "this master has no such route" or the master's own "not found" (an unknown model no longer reads "upgrade master"); `refiner_status`, `refiner_configure`, `focus_scope` and `curate_model` say what to install; `hand_over` names the step that fits (`mcp-url` and an unreachable MCP server no longer ask to reconfigure or to grant), puts `model` in every hint and takes `requestId` for a retry; `curate_model ask` hands `requestId` and `supersedes` to the Interview (an own question stayed in every digest); `refine_model` takes `includeDeferred`; `get_net_definition` carries the net's confirmations and flags again; wording says sources, not code.
- **Focus 1.5.2** (`agentic-net-apps/examples/refiner`). The question round and the refinement pass route every scope form: domain:, tag:, net:, any: as a scope, `session::net` as a net, a bare word as a level. A test renders every Focus prompt with each scope form.
- **`ground_model` lists a net's claims once** (`agentic-net-mcp` - `tools/refine.ts`). The chains share their upper nets; a net already listed repeats only key, title, level, confirmation and `sameAs` (a live model's read: 197 KB to 114 KB); `full:true` repeats everything.
- **Executor polls piled up on a slow master** (`agentic-net-executor` - `MasterPollingService`). The 2 s poll loop started a new poll for every model whether or not the previous one had returned, and gave up after 5 s; against a master that needed 8.8 s per poll (Desktop, 2026-10-14) every poll was both abandoned and still running, and no command lane could receive work. A model is now polled again only after its previous poll has finished, and the timeout is `executor.poll.timeout-ms` (default 15 s).
